# «سامانهٔ جامع منابع انسانی» — اجرای محلی با دادهٔ واقعی (Postgres)

این سند وضعیت نصب و اجرای همین رایانه را ثبت می‌کند: پایگاه‌دادهٔ واقعی، راه‌اندازی
وب‌سرویس، و راه‌های شروع/توقف. برای محیط عملیاتی واقعی به
`docs/deployment-runbook-fa.md` نگاه کنید.

---

## ۱. چه چیزی نصب شد

| جزء | مسیر / مقدار |
|---|---|
| PostgreSQL | نسخهٔ ۱۷٫۲ (بستهٔ همراه/embedded)، `%USERPROFILE%\tools\pg` |
| پوشهٔ دادهٔ کلاستر | `%USERPROFILE%\tools\pg\data` |
| فایل لاگ پایگاه‌داده | `%USERPROFILE%\tools\pg\pg.log` |
| نشانی شنود | `127.0.0.1:5432` (فقط محلی) |
| دیتابیس | `hrms` |
| کارابر (superuser) | `hrms` — ورود محلی با `trust` |
| سرور سامانه | `server\bin\hrmsd.exe` روی `127.0.0.1:8080` |
| رابط وب | همان سامانه روی ریشه سرو می‌شود: `design/prototype` |

> چرا این بستهٔ Postgres: بستهٔ رسمی EDB (get.enterprisedb.com) از این شبکه قابل
> دریافت نبود؛ بستهٔ جاسازی‌شدهٔ `embedded-postgres-binaries-windows-amd64` (نسخهٔ
> ۱۷٫۲) از Maven Central گرفته شد و باینری‌های آن extract شد. همین بسته ابزار خط
> فرمان `psql` را همراه ندارد (بخش ۵ را ببینید).

## ۲. پیکربندی سامانه

فایل `server\.env` (در `.gitignore` است و نباید به مخزن برود):

```
HRMS_DATABASE_URL=postgres://hrms@127.0.0.1:5432/hrms?sslmode=disable
HRMS_ORG=bandar_imam
HRMS_JWT_SECRET=<کلید تصادفی ۳۲ بایتی>
```

سرور هنگام بالا آمدن، مهاجرت‌ها را از `server/migrations` و
`server/internal/modules/*/migrations` پیدا و اعمال می‌کند (تکرار اجرا بی‌خطر است).

## ۳. اجرا

ساده‌ترین راه: روی `start-HRMS.bat` دوبار کلیک کنید. این اسکریپت:

1. اگر کلاستر محلی موجود و خاموش باشد، آن را بالا می‌آورد؛
2. اگر سرور از قبل در حال اجرا باشد، فقط مرورگر را باز می‌کند؛
3. در نبود Infisical، از `server\.env` استفاده می‌کند؛
4. `server\bin\hrmsd.exe` را روی `127.0.0.1:8080` اجرا می‌کند.

اجرای دستی (بدون اسکریپت):

```bash
# ۱) پایگاه‌داده
export PATH="$HOME/tools/pg/bin:$PATH"
pg_ctl -D "C:\Users\<user>\tools\pg\data" \
       -l "C:\Users\<user>\tools\pg\pg.log" \
       -o "-p 5432 -c listen_addresses=127.0.0.1" start   # بدون -w؛ بخش ۳٫۱ را بخوانید

# ۲) سرور سامانه
cd server
./bin/hrmsd.exe -addr 127.0.0.1:8080 -org bandar_imam \
  -web ../design/prototype -root . -env .env
```

توقف پایگاه‌داده: `pg_ctl -D "<data>" stop`.

### ۳٫۱ نکتهٔ مهم ویندوز: پایگاه‌داده را در کنسول جداگانه بالا بیاورید

اگر `pg_ctl start` را از درون یک اسکریپت یا ابزار اجرا کنید و **خودِ فرمان پیش از
آماده شدن کلاستر کشته شود**، پست‌مستر زنده می‌ماند ولی دیگر نمی‌تواند فرآیند فرزند
بسازد؛ نشانه‌اش این سطرها در `%USERPROFILE%\tools\pg\pg.log` است:

```
LOG:  server process (PID …) was terminated by exception 0xC0000142
LOG:  all server processes terminated; reinitializing
LOG:  database system is shut down
```

و سرور سامانه با این خطا بالا نمی‌آید:
`اتصال به پایگاه‌داده برقرار نشد: … wsarecv: An existing connection was forcibly closed`.

درمان: کل فرآیندهای `postgres.exe` را ببندید و از نو با یک **کنسول مستقل** بالا
بیاورید — ساده‌ترین راه همان اجرای `start-HRMS.bat` با دوبار کلیک است. برای اجرای
دستی از `pg_ctl` بدون پرچم `-w` استفاده کنید تا فرمان فوراً برگردد و کلاستر بدون
وقفه ساخته شود.

## ۴. آن‌چه آزموده شد

- `store=postgres` در لاگ راه‌اندازی؛ شرکت فعال «پتروشیمی بندر امام» با ۳۰ ماژول.
- مهاجرت‌ها: `found=7 applied=7` در اجرای نخست و `applied=0` در اجرای بعدی
  (بی‌خطر و تکرارپذیر).
- `GET /` → ۲۰۰ و رابط وب سرو شد؛ `GET /healthz` و `/readyz` → ۲۰۰؛
  `GET /api/v1/orgs` بدون ورود → ۴۰۱.
- ورود (`POST /api/v1/auth/login`) با `admin`/`demo` → ۲۰۰ و `GET /api/v1/auth/me` → ۲۰۰.
- ساخت قرارداد (`POST /api/v1/contracts/contracts`) → ۲۰۱، سپس **ری‌استارت سرور** و
  بازخوانی همان قرارداد → ۲۰۰ (یعنی داده واقعاً در Postgres ماند، نه در حافظه).
  پس از آزمون، همان قرارداد آزمایشی حذف شد تا پایگاه‌داده تمیز بماند.
- **اثبات اشتراک داده روی Postgres:** نمونهٔ دومی از سرور روی درگاه دیگر بالا آمد و
  همان قرارداد `CT-1405-0203` و همان ۱۲ کارمند را از همان پایگاه‌داده خواند؛ در
  لاگش `پایگاه‌دادهٔ Postgres متصل شد driver=postgres` و
  `انبار قراردادها روی Postgres فعال است` دیده می‌شود. اگر داده در حافظهٔ هر فرآیند
  بود، نمونهٔ دوم چیزی نمی‌دید.

## ۵. آزمون دودی خودکار (پُری ماژول‌ها و چرخهٔ رکوردها)

همین چیزی که در بخش ۴ دستی آزموده شد، حالا یک آزمون خودکار Go است:
`server/internal/bootstrap/postgres_smoke_test.go`. سرور واقعی (همان `NewDeps` و
`NewHandler`) روی پایگاه‌داده بالا می‌آید، مهاجرت‌ها اعمال و دادهٔ نمونه بذرکاری می‌شود و
سپس سه چیز سنجیده می‌شود:

1. **پُری همهٔ ماژول‌ها** — هر ماژول رکوردی باید در *هر نوع رکورد* دست‌کم یک رکورد
   داشته باشد و پنج ماژول با انبار اختصاصی (داشبورد، کارکنان، قراردادها، خدمات پرسنلی،
   احکام) در مسیر فهرست خودشان ناتهی باشند.
2. **چرخهٔ ایجاد ← جستجو ← ویرایش ← حذف** روی هر نوع رکورد در همهٔ ماژول‌ها (روی
   دادهٔ واقعی Postgres، با قواعد همان دامنه؛ مقادیر فیلدهای اجباری از رکورد نمونهٔ خود
   همان نوع گرفته می‌شود تا هیچ فهرست مجازی در آزمون تکرار نشود).
3. **اشتراک داده بین دو نمونهٔ سرور** روی همان پایگاه‌داده: رکوردی که نسخهٔ اول می‌سازد
   باید نسخهٔ دوم بخواند؛ این تنها چیزی است که حافظه‌ای‌بودن انبار را رد می‌کند.

اجرای محلی (نیازمند یک پایگاه‌دادهٔ آزمایشی؛ نه پایگاه‌دادهٔ کار):

```bash
cd server
export HRMS_TEST_DATABASE_URL="postgres://hrms@127.0.0.1:5432/hrms_smoke?sslmode=disable"
go test -count=1 -v -run PostgresSmoke ./internal/bootstrap/
# یا از ریشهٔ مخزن:
make smoke-postgres
```

در CI همین آزمون در کار «آزمون دودی Postgres» روی سرویس `postgres:17` اجرا می‌شود
(`.github/workflows/ci.yml`). بدون متغیر `HRMS_TEST_DATABASE_URL` آزمون رد می‌شود، پس
`go test ./...` محلی به پایگاه‌دادهٔ توسعه‌ای کسی دست نمی‌زند.

> **آنچه این آزمون پیدا کرد:** نوع رکورد «آگهی شغلی» استخدام و «گروه شغلی» طبقه‌بندی
> مشاغل هر دو پیشوند شناسهٔ `JOB` داشتند؛ چون جدول رکوردها مشترک است و کلید اصلی‌اش
> خودِ شناسه، رکوردهای این دو ماژول روی هم می‌نوشتند و نوع رکورد آگهی در فهرست خودش
> خالی می‌ماند. پیشوند آگهی به `JBP` تغییر کرد و یک دروازهٔ بدون‌پایگاه‌داده هم اضافه شد
> (`TestRecordKindIDPrefixesAreUniqueAcrossModules`) تا یکتایی پیشوندها در CI تضمین شود.

## ۶. محدودیت‌ها و گام‌های بعدی

1. **ابزار SQL خط فرمان نیست.** بستهٔ Postgres همراه `psql` ندارد؛ برای اجرای SQL
   دستی یا یک بستهٔ کامل PostgreSQL نصب کنید یا یک ابزار کوچک Go با همان درایور
   `lib/pq` اضافه کنیم.
2. **احراز هویت `trust` روی loopback است.** این برای همین رایانه امن است، ولی برای
   استقرار واقعی باید رمز بگذارید، `listen_addresses` را محدود کنید و TLS بگذارید.
3. **فقط محلی است.** برای دسترسی از رایانهٔ دیگر، `-addr 0.0.0.0:8080` بدهید و در
   فایروال اجازهٔ ورودی بدهید؛ ترجیحاً پشت یک پروکسی معکوس با TLS.
4. **دادهٔ نمونه در رابط.** برخی صفحه‌ها در نبود رکورد، دادهٔ نمایشی می‌سازند؛
   دادهٔ واقعی از همان API/صفحهٔ خود ماژول ثبت می‌شود.
