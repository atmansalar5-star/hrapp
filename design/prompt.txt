دستورالعمل طراحی رابط کاربری سیستم جامع منابع انسانی
بخش ۱: تعریف نقش‌های کاربری (User Roles)
سیستم منابع انسانی باید بر اساس نقش (Role-Based Access Control) طراحی شود. ایجنت Freebuff باید برای هر نقش، داشبورد و منوی مجزا تولید کند.

نقش‌های اصلی مورد نیاز:

نقش	دسترسی‌ها
مدیر منابع انسانی (HR Manager)	دسترسی کامل به تمام ماژول‌ها، تأیید نهایی، گزارش‌های کلان
کارشناس منابع انسانی (HR Specialist)	مدیریت کارکنان، استخدام، آموزش، ورود داده
مدیر واحد (Line Manager)	تأیید مرخصی، ارزیابی عملکرد، مشاهده کارکنان واحد خود
کارمند (Employee)	مشاهده اطلاعات شخصی، درخواست مرخصی، مشاهده فیش حقوقی، ثبت درخواست‌ها
مدیر سیستم (Admin)	مدیریت کاربران، نقش‌ها، تنظیمات سیستم، لاگ حسابرسی
بخش ۲: منوهای اصلی سیستم (Main Menu Structure)
ایجنت باید منوهای زیر را به عنوان ساختار اصلی طراحی کند:

۱. داشبورد (Dashboard)

ویجت‌های آماری بر اساس نقش (تعداد کارکنان، درخواست‌های در انتظار تأیید، مرخصی‌های جاری)

نمودارهای روند استخدام، توزیع نیرو در واحدها

اعلان‌های اخیر و اقدامات سریع

۲. مدیریت کارکنان (Employee Management)

فهرست کارکنان: جستجو، فیلتر بر اساس واحد/وضعیت/نوع قرارداد، عملیات CRUD

پرونده کارمند: اطلاعات شخصی، سوابق شغلی، مدارک، مهارت‌ها، اطلاعات قرارداد

ساختار سازمانی: نمودار درختی واحدها و پست‌ها، امکان افزودن/ویرایش واحد

۳. استخدام و جذب (Recruitment)

درخواست‌های نیرو: ثبت و پیگیری درخواست استخدام از واحدها

آگهی‌های شغلی: مدیریت آگهی‌ها و کانال‌های انتشار

متقاضیان: بانک رزومه، وضعیت بررسی، زمان‌بندی مصاحبه

فرآیند جذب: گردش کار از غربالگری تا پیشنهاد نهایی

۴. حضور و غیاب (Attendance & Time)

ثبت تردد: مشاهده و اصلاح رکوردهای ورود/خروج

مرخصی و ماموریت: درخواست، تأیید، موجودی مرخصی

اضافه‌کاری: ثبت، تأیید، محاسبه

تقویم: نمایش شیفت‌ها و مرخصی‌ها به صورت ماهانه

۵. حقوق و دستمزد (Payroll)

پردازش حقوق: اجرای محاسبات ماهانه، فرمول‌ها (مالیات، بیمه، اضافه‌کاری)

فیش حقوقی: نمایش و دانلود فیش برای کارمند

اجزای حقوق: تعریف آیتم‌های حقوقی، فرمول‌ها، معافیت‌ها

گزارش‌های مالی: لیست پرداخت، گزارش بیمه، گزارش مالیات

۶. ارزیابی عملکرد (Performance)

دوره‌های ارزیابی: تعریف و مدیریت دوره‌ها

فرم‌های ارزیابی: طراحی شاخص‌ها (KPI)، وزن‌دهی

نتایج: مشاهده و تحلیل نتایج، بازخورد

۷. آموزش و توسعه (Training)

دوره‌های آموزشی: تعریف، ثبت‌نام، ظرفیت

سوابق آموزشی: گواهی‌نامه‌ها، مهارت‌های کسب‌شده

نیازسنجی: تحلیل شکاف مهارتی

۸. رفاه و خدمات (Welfare)

تسهیلات: وام، بیمه تکمیلی، سفر

درخواست‌ها: ثبت و پیگیری درخواست‌های رفاهی

۹. گزارش‌ها (Reports)

گزارش‌های عملیاتی (لیست پرسنل، ترک خدمت، ورود و خروج)

گزارش‌های تحلیلی (نرخ جذب، نرخ ترک، بهره‌وری)

خروجی Excel/PDF

۱۰. تنظیمات (Settings) [مخصوص Admin و HR Manager]

مدیریت کاربران و نقش‌ها

تنظیمات سازمانی (واحدها، پست‌ها، تقویم کاری)

پارامترهای سیستم (کدهای دسترسی، سطوح تأیید)

لاگ حسابرسی

بخش ۳: دستورالعمل طراحی Wireframe (Low-Fidelity)
دستور ۳-۱ — ساختار هر صفحه:
هر صفحه Wireframe باید شامل عناصر زیر باشد:

Header: لوگو، نام کاربر، اعلان‌ها، منوی کاربر

Sidebar: منوی ناوبری اصلی (بر اساس نقش، آیتم‌های غیرمجاز مخفی یا غیرفعال)

Main Content Area: جدول داده، فرم، یا نمودار

Action Bar: دکمه‌های عملیات (ایجاد، ویرایش، حذف، خروجی)

Breadcrumb: مسیر ناوبری (مثال: منابع انسانی > کارکنان > پرونده)

دستور ۳-۲ — اصول طراحی جدول:

ستون‌های جدول: شناسه، نام، واحد، پست، وضعیت، عملیات

قابلیت مرتب‌سازی (Sort) و فیلتر (Filter) در سرستون‌ها

صفحه‌بندی (Pagination) در پایین جدول

نمایش تعداد رکورد در بالای جدول

دستور ۳-۳ — اصول طراحی فرم:

گروه‌بندی فیلدها بر اساس منطق (اطلاعات شخصی، اطلاعات شغلی، اطلاعات قرارداد)

استفاده از Tab یا Accordion برای فرم‌های طولانی

فیلدهای اجباری با ستاره (*) مشخص شوند

پیام‌های خطا در کنار فیلد مربوطه

دستور ۳-۴ — اصول طراحی داشبورد:

چیدمان کارتی (Card-based) برای ویجت‌ها

هر کارت شامل: عنوان، مقدار عددی، آیکون، لینک به جزئیات

نمودارها در بالای صفحه، جداول در پایین

بخش ۴: دستورالعمل طراحی Prototype (High-Fidelity)
دستور ۴-۱ — ابزار پیشنهادی: Figma (برای طراحی UI و Prototype تعاملی)

دستور ۴-۲ — سطح وفاداری (Fidelity):
Prototype باید High-Fidelity باشد؛ یعنی:

شامل رنگ‌ها، فونت‌ها و آیکون‌های واقعی

قابلیت کلیک بین صفحات

نمایش حالت‌های Hover و Active

شبیه‌سازی داده‌های واقعی (نمونه)

دستور ۴-۳ — تعاملات مورد نیاز:

کلیک روی آیتم منو → انتقال به صفحه مربوطه

کلیک روی ردیف جدول → باز شدن پرونده

کلیک روی دکمه "ایجاد" → باز شدن فرم

تأیید فرم → بازگشت به جدول با پیام موفقیت

فیلتر و جستجو → به‌روزرسانی جدول

دستور ۴-۴ — صفحات حداقلی برای Prototype اولیه:

صفحه ورود (Login)

داشبورد کارمند (Employee Dashboard)

داشبورد مدیر (Manager Dashboard)

فهرست کارکنان (Employee List)

پرونده کارمند (Employee Profile)

فرم درخواست مرخصی (Leave Request Form)

صفحه تأیید مرخصی (Leave Approval - Manager View)

بخش ۵: دستورات اختصاصی برای ایجنت Freebuff
دستور ۵-۱ — تولید User Flow:
ایجنت باید برای هر نقش، یک User Flow ترسیم کند. فرمت خروجی: فلوچارت با نمادهای استاندارد (مستطیل = صفحه، لوزی = تصمیم، فلش = انتقال)

دستور ۵-۲ — تولید Wireframe:
برای هر صفحه، یک Wireframe ساده (خط‌کشی شده) با مشخص کردن:

محل قرارگیری Header، Sidebar، Content

نوع عناصر (جدول، فرم، دکمه، نمودار)

برچسب فارسی برای هر عنصر

دستور ۵-۳ — رعایت راست‌چین (RTL):

منوی Sidebar در سمت راست قرار گیرد

متن‌ها راست‌چین باشند

ترتیب ستون‌های جدول از راست به چپ باشد

دستور ۵-۴ — نام‌گذاری فایل‌ها:

Wireframe: WF_[نام-صفحه]_[نقش].fig

User Flow: UF_[نام-فرآیند]_[نقش].fig

Prototype: PT_HRMS_[نسخه].fig

دستور ۵-۵ — مستندسازی:
ایجنت باید برای هر صفحه، یک توضیح متنی فارسی شامل موارد زیر تولید کند:

هدف صفحه

عناصر اصلی

اقدامات قابل انجام

نقش‌های مجاز

خلاصه اقدامات برای ایجنت
تعریف نقش‌ها (۵ نقش اصلی)

طراحی ساختار منو (۱۰ منوی اصلی)

تولید User Flow برای هر نقش

طراحی Wireframe برای ۷ صفحه حداقلی

تبدیل به Prototype تعاملی در Figma

مستندسازی هر صفحه به فارسی

رعایت RTL در تمام خروجی‌ها
